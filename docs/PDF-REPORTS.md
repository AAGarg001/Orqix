# Branded report downloads

All generated PDFs now follow the same A A GARG & CO design: business reports, test payment receipts, commercial tax invoices and internal workflow exports. Financial documents use prominent amounts, aligned party/reference blocks, clear tax/discount totals and human-readable India timestamps. Standard receipts/invoices fit one page; long addresses and workflow records paginate. Original invoice snapshots, tax calculations and verified-payment rules are preserved.

Optional-logo POST downloads are also supported at `/api/client/billing/test/orders/:id/receipt`, `/api/client/billing/invoices/:id/pdf` and `/api/platform/reports/export?format=pdf`. Their original GET downloads remain available. UI buttons now open the same optional-logo popup, including internal workflow PDF export. Tenant ownership, billing roles and internal report permissions remain enforced. Uploaded source PDFs are not modified.

Shared financial/workflow renderer: `apps/api/src/pdf/documents.ts`; tests: `documents.test.ts`. Latest verification: 62 API tests and four browser tests pass, including the full client route sweep, logo report downloads and sandbox purchase UI. Real Uflex receipt download opens the popup and returns a one-page branded PDF. Temporary real receipt and sample invoice/workflow render files were deleted after inspection.

Client Reports PDF buttons now open a branding modal. Company logo is optional: download directly without one, or upload a PNG/JPEG up to 2 MB and maximum 4096px / 16 million pixels. Browser preview, remove/replace and a download-without-logo action are provided. The supplied A A GARG & CO SVG is always included; optional client branding appears alongside it on every page.

The PDF renderer uses vector branding, an executive summary with six formatted metrics, source-as-of and generation times in India time, category/FY charts, source/retention details and readable calculation definitions. Detail reports use curated columns, landscape pages, alternating row backgrounds, repeated headers, controlled wrapping and page numbers. Summary does not repeat raw metrics as unformatted data rows. Procurement PDFs include every matching record, plus supplier, registration and unit analysis. Other detail report types show up to 100 matching records with an explicit notice; Excel remains available for complete structured exports.

GET `/api/client/axis/export?...&format=pdf` still downloads an uncustomized branded report. POST to the same URL accepts multipart field `logo` (optional). Existing tenant ownership and published-snapshot filtering apply to both. Unsupported images/oversized files are rejected. Logos and generated PDF bytes are handled in memory and never archived; only existing minimal download history is retained. Temporary development PDF samples/screenshots were deleted after layout verification.

Implementation: `apps/api/src/axis/report-pdf.ts`, `report-pdf.test.ts`, Axis export router, `apps/web/src/client/PdfDownloadButton.tsx`, `pdf-download.css` and report catalog buttons. The SVG renderer dependency is `svg-to-pdfkit`. Development loads the public SVG; the Docker runtime uses the copied web-dist SVG fallback.

Verification: 59 API/unit tests passed, including summary page count, embedded company image, multi-page detail rendering and malformed/oversized logo rejection. Axis and Razorpay browser tests both passed; Axis includes actual logo-upload/customized PDF download and optional no-logo download. Real Uflex PDFs were rendered for inspection; summary is two pages, detail reports have repeating headers/footers and no extra blank footer pages. Popup fits 1568/768/390/320px. Production builds passed.

The supplied Razorpay TEST credentials were placed only in the local backend `.env`, which is ignored by source control. Read-only authentication returned HTTP 200; restarted backend confirms test checkout readiness. Secret values are never returned to the client or included in these docs. No payment was initiated by development verification.
